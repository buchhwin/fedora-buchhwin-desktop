# The desktop itself.
#
# ⚠️ Installed with --setopt=install_weak_deps=False, deliberately.
# Fedora's niri package RECOMMENDS waybar, alacritty, fuzzel and swaylock, and
# its shipped default config even has `spawn-at-startup "waybar"`. We replace
# all four, so pulling them in would put a second bar on the screen.
niri
quickshell
qt6-qtdeclarative           # quickshell's runtime
qt6-qtdeclarative-devel     # qmllint/qmlformat, used by CI and `bhctl doctor`

# Greeter. greetd, not SDDM: the greeter is our own Quickshell surface, so it
# uses the same palette, fonts and code as the lock screen instead of needing a
# second theme maintained in a second format. greetd itself is 2 packages.
# ⚠️ SDDM is only removed once the new greeter is proven to reach a desktop on
# the VM — a broken greeter means no way to log in at all.
greetd

# Terminal.
kitty

google-noto-sans-cjk-fonts

jetbrains-mono-fonts

# Files, network shares and cloud storage.
#
# nautilus is not merely "a file manager". From niri's own shipped wiki:
# xdg-desktop-portal-gnome is REQUIRED for screencasting, and since v47 that
# portal uses nautilus as the file chooser — so this is the Open/Save dialog of
# every application. Both portals below are therefore correct, not redundant.
# (Escape hatch if it ever bites: org.freedesktop.impl.portal.FileChooser=gtk;
# in niri-portals.conf.)
#
# Measured against the Qt alternative: nautilus + gvfs + online accounts is
# 11 packages / 17 MiB; dolphin pulls 68 packages / 216 MiB of KDE frameworks.
nautilus
gvfs
gvfs-smb
gvfs-nfs
gvfs-fuse                   # makes gvfs mounts visible to non-GTK programs too
gvfs-goa                    # Google Drive and friends, via online accounts
gnome-online-accounts
gnome-online-accounts-gtk   # standalone account setup; no GNOME Settings needed

# ⚠️ THE FILE MANAGER QUESTION, ANSWERED. It said "OPEN DECISION — see docs/
# for the question" while nautilus sat installed above and set as the default in
# Config.qml, and the question was in no document. Decided on 5 August 2026, in
# his words: "nautilus passt".
#
# Every mature Linux file manager is GTK (nautilus, nemo, thunar) or Qt
# (dolphin, pcmanfm-qt), so "no GTK" cannot be met by any of them. The rule is
# about the interface WE build — see docs and the project rules — and a file
# manager is somebody else's program, recoloured by the generated GTK theme like
# every other foreign window. nautilus is also load-bearing beyond browsing
# files: xdg-desktop-portal-gnome uses it as the file chooser, so it is the
# Open/Save dialog of every application.
