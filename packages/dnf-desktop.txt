# ⚠️ greetd IS NOT HERE ANY MORE, and its absence is the decision.
#
# It was installed from the first commit and never configured: no
# /etc/greetd/config.toml is written, no greetd.service is enabled, and there is
# no greeter surface under shell/ui/ for it to start. Meanwhile lib/30-desktop.sh
# enables sddm and lib/70-services.sh patches /etc/pam.d/sddm for the keyring —
# so the machine installed one login manager it never used alongside another it
# did. That is the same shape as bluez, which shipped a Bluetooth panel with no
# daemon behind it for four milestones: a package present, and the one step that
# would make it do something missing.
#
# It comes back with M9, in the same commit as the greeter and the config that
# starts it. docs/CHECKLIST.md keeps the condition for removing sddm: only once
# our own greeter demonstrably reaches a desktop, because a broken greeter means
# no way to log in at all.

# The authorisation dialog, and the one place this desktop uses somebody else's
# window on purpose.
#
# ⚠️ IT CANNOT BE BUILT IN QUICKSHELL. A polkit agent has to REGISTER itself
# with org.freedesktop.PolicyKit1.Authority over D-Bus and answer challenges;
# quickshell has no interface for that. Without one, "turn the wifi radio off"
# is refused with "Not authorized" and nothing happens — a switch that does
# nothing, which is exactly what this project is not allowed to ship.
#
# Chosen and approved on 6 August 2026 after asking, because the rules say to
# ask before taking on a foreign program rather than doing it quietly. It is a
# background daemon with no window of its own; the dialog it does show is GTK,
# so the generated GTK theme colours it like every other foreign window — no
# second colour vocabulary enters the desktop, which is what the "no GTK" rule
# is actually about.
#
# Measured before adding: `mate-polkit-1.28.1`, in the `fedora` repo (no COPR),
# and `dnf repoquery --requires --resolve` returns nothing extra to install.
# One file: /usr/libexec/polkit-mate-authentication-agent-1.
mate-polkit

# Files, network shares and cloud storage.
#
# nautilus is not merely "a file manager". From niri's own shipped wiki:
# xdg-desktop-portal-gnome is REQUIRED for screencasting, and since v47 that
# portal uses nautilus as the file chooser — so this is the Open/Save dialog of
# every application. Both portals below are therefore correct, not redundant.
# (Escape hatch if it ever bites: org.freedesktop.impl.portal.FileChooser=gtk;
# in niri-portals.conf.)
#
# Measured against the Qt alternative: nautilus + gvfs + online accounts is
# 11 packages / 17 MiB; dolphin pulls 68 packages / 216 MiB of KDE frameworks.
nautilus

gvfs-goa                    # Google Drive and friends, via online accounts

# ⚠️ THE FILE MANAGER QUESTION, ANSWERED. It said "OPEN DECISION — see docs/
# for the question" while nautilus sat installed above and set as the default in
# Config.qml, and the question was in no document. Decided on 5 August 2026, in
# his words: "nautilus passt".
#
# Every mature Linux file manager is GTK (nautilus, nemo, thunar) or Qt
# (dolphin, pcmanfm-qt), so "no GTK" cannot be met by any of them. The rule is
# about the interface WE build — see docs and the project rules — and a file
# manager is somebody else's program, recoloured by the generated GTK theme like
# every other foreign window. nautilus is also load-bearing beyond browsing
# files: xdg-desktop-portal-gnome uses it as the file chooser, so it is the
# Open/Save dialog of every application.
